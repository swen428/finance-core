# Canonical Decimal serialization

`canonical_decimal_str` accepts finite `Decimal` values whose canonical plain text fits within 1,048,576 ASCII characters, including any sign and decimal point. It emits the exact numeric value, removes insignificant trailing fractional zeros, maps positive and negative zero to `0`, and never emits scientific notation. An overlong representation raises `MoneyValidationError` before expanded text is constructed. The result and limit do not depend on the active Decimal precision, rounding mode, traps or flags. Currency-scaled amounts still use `canonical_money_str` and its separate validation contract.

Canonical JSON, snapshots, audit events and statement identities retain their existing contract versions and hash domains. Stored JSON bytes, hashes and public IDs are immutable. Evidence created with the previous serializer remains verifiable and replayable when its canonical amount was already exact and fits the current representation bound. A previously accepted statement whose fingerprint was rounded by the old ambient context can fail row verification or source replay under the exact serializer. Such records remain unchanged and fail closed; this change does not infer a historical Decimal context, rewrite an identity, or accept a mismatched hash. Recovery for an affected record requires a separate evidence-based procedure.

The fixed output limit bounds expansion of short exponent-form inputs, including values parsed from statement CSV files. It is a representation resource bound, not a monetary amount limit. Zero remains `0` even when its stored exponent is extreme.
